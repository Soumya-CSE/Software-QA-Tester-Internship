## 2. Project Objective

The objective of this project is to perform complete manual testing of the OrangeHRM web application and identify functional and UI defects.

The project will cover test planning, test scenario creation, test case preparation, test execution, defect reporting, screenshot evidence, and Requirements Traceability Matrix (RTM).

---

## 3. Scope

### In Scope

The following modules will be tested:

* Login
* Dashboard
* Employee Management
* Employee Search
* Add Employee
* Edit Employee
* Delete Employee
* Leave Management
* Logout

### Out of Scope

The following areas are outside the scope of this Week 1 project:

* Performance testing
* Load testing
* Security penetration testing
* API automation
* Mobile application testing
* Database testing

---

## 4. Testing Approach

Testing will be performed manually using predefined test cases.

The following testing techniques will be used:

* Functional Testing
* UI Testing
* Positive Testing
* Negative Testing
* Boundary Value Testing
* Exploratory Testing
* Regression Testing
* Smoke Testing

Test results will be recorded as:

* PASS
* FAIL
* BLOCKED
* NOT EXECUTED

## 9. Defect Management

Any unexpected behavior found during test execution will be documented as a defect.

Each defect will contain:

* Bug ID
* Bug Title
* Module
* Severity
* Priority
* Preconditions
* Steps to Reproduce
* Expected Result
* Actual Result
* Status
* Screenshot

### Severity

| Severity | Description                                        |
| -------- | -------------------------------------------------- |
| Critical | Application or major functionality is unusable     |
| High     | Major functionality is seriously affected          |
| Medium   | Functionality is affected but workaround may exist |
| Low      | Minor functional or UI issue                       |

### Priority

| Priority | Description                         |
| -------- | ----------------------------------- |
| High     | Fix immediately                     |
| Medium   | Fix during normal development cycle |
| Low      | Fix when resources are available    |

---

## 10. Bug Life Cycle

The expected defect workflow is:

```text
New
 ↓
Assigned
 ↓
Open
 ↓
Fixed
 ↓
Retest
 ↓
Verified
 ↓
Closed
```

If the defect is still present after retesting:

```text
Retest
  ↓
Failed
  ↓
Reopened
```

## 12. Requirements Traceability Matrix

The RTM will establish a relationship between requirements, test cases, execution results, and defects.

```text
Requirement
     ↓
Test Case
     ↓
Test Execution
     ↓
PASS / FAIL
     ↓
Bug ID
```

Example:

| Requirement ID | Requirement                             | Test Case ID | Status | Bug ID      |
| -------------- | --------------------------------------- | ------------ | ------ | ----------- |
| ORH-REQ-001    | User should be able to login            | TC-LOGIN-001 | PASS   | —           |
| ORH-REQ-002    | Admin should be able to add employee    | TC-EMP-001   | PASS   | —           |
| ORH-REQ-003    | Admin should be able to search employee | TC-EMP-002   | FAIL   | BUG-ORH-001 |

## 13. Entry Criteria

Testing will begin when:

* Application is accessible.
* Test environment is available.
* Test requirements are identified.
* Test scenarios are prepared.
* Test data is available.
* Required browser is installed.

---

## 14. Exit Criteria

Testing will be considered complete when:

* All planned test cases have been executed.
* Major test scenarios have been covered.
* All identified defects have been documented.
* Screenshots have been attached where required.
* RTM has been updated.
* Test results have been reviewed.

---

## 15. Risks and Assumptions

### Risks

* Demo application may be unavailable.
* Application data may change during testing.
* Some features may not be available in the demo environment.
* Browser compatibility may affect results.
* Test execution may be affected by network issues.

### Assumptions

* The application is accessible during testing.
* Test credentials are available.
* Required modules are available in the selected environment.
* Testing is performed using a supported web browser.
